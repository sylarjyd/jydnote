# 故障排查

先按下面的顺序定位，大部分问题能在前两步解决：

1. 看左下角状态按钮的提示。
2. 打开「设置」→「测试连接」，区分是对话侧还是嵌入侧失败。
3. 看文档列表里的错误行，判断是导入 / 解析 / 嵌入中的哪一步。
4. 用 `npm run smoke` 排除核心链路问题。

> 求助或截图时不要包含 API Key、完整设置文件或含敏感内容的笔记原文。

## 1. 模型状态与连接

### 状态显示「待配置模型」

对话或嵌入至少一侧没有可用 Key，或模型名为空。

- 在「设置」里填写 DeepSeek / 百炼 API Key，或设置环境变量。
- 切到「LM Studio / API」后模型名默认为空，先「测试连接」，再从模型标签点选。
- Key 留空时才会读取环境变量，界面填写优先。
- 保存后再点一次状态按钮刷新。

### 状态显示「部分模型未就绪」

悬停状态按钮，或看「测试连接」的两行结果：

- 对话侧失败：不能问答，但可以导入。
- 嵌入侧失败：不能导入，也不能提问（问题也需要向量化）。

### 状态显示「模型未就绪」

通常是网络、地址、余额或模型名问题。继续看下一节的具体错误。

## 2. 云端错误

### 「未配置 DeepSeek API Key，请在设置中填写（或设置环境变量 DEEPSEEK_API_KEY）」

设置里的 Key 和环境变量都为空。填入 Key，或启动应用前设置环境变量。

### 「API Key 无效或已过期，请在设置中检查」

- Key 复制不完整，或前后带空格。
- Key 属于另一个服务商，或已经删除 / 轮换。
- Base URL 与 Key 不匹配，例如把百炼 Key 填到了 DeepSeek。

### 「账户余额不足或服务未开通」

到对应控制台检查余额、免费额度或模型开通状态。百炼需要开通对应模型服务。

### 「请求过于频繁或额度受限（HTTP 429）」

触发限流或并发限制。等待一段时间，或降低导入并发（当前导入本身是串行的，通常是账号级限流）。

### 「模型不存在或不可用」

- 检查模型名拼写：`deepseek-flash`、`text-embedding-v4`。
- 自定义网关可能没有上架该模型。
- 百炼还需要确认模型在对应业务空间可用。

### 「无法连接…」或「连接…超时」

应用连不上服务地址。检查：

- 是否能正常访问 `api.deepseek.com` 或 `dashscope.aliyuncs.com`。
- Base URL 是否多了 / 少了路径。百炼默认地址必须包含 `/compatible-mode/v1`。
- 公司代理是否拦截；必要时把这两个域名加入代理白名单。
- 本地 Ollama 地址需要把 `127.0.0.1` 加入 `NO_PROXY`，避免请求被代理转发。
- 自定义网关是否支持 HTTPS 与流式响应。

### 「测试连接」成功但问答失败

可能原因：

- `/models` 可用，但 `/chat/completions` 被网关限制或超时。
- 网关不支持 SSE 流式返回。
- 账号额度在测试后耗尽。

用同一套配置在终端直接请求接口，确认流式返回是否正常。

### 百炼相关错误

| 错误 | 处理 |
| --- | --- |
| 文本超出嵌入模型单条上限（8192 tokens） | 减小「分块大小」，重建该文档 |
| 嵌入结果数量不匹配 | 服务端返回异常或网关改写了响应，重试；持续出现则更换地址 |
| 嵌入维度不匹配 | 设置里的维度与服务端实际返回不一致，改成允许的维度并重建索引 |
| 返回了空向量 | 检查模型名、输入内容；空白文本会被替换为一个空格 |

百炼单批最多 10 条，应用会自动分批；不需要手动调整批次。

### LM Studio / OpenAI 兼容服务

#### 「无法连接 OpenAI 兼容服务」

- 确认 LM Studio 已启动 Local Server，默认端口 `1234`。
- 服务地址必须包含 `/v1`，例如 `http://127.0.0.1:1234/v1`；地址错误时通常表现为连接失败或 404。
- 代理环境把 `127.0.0.1` 加入 `NO_PROXY`。
- 使用远程兼容 API 时，确认地址可访问且支持 HTTPS。

#### 「请填写或从模型列表选择…模型」

切换提供方后模型名会清空，这是为了避免把上一家的模型名误发过去。先点「测试连接」，从返回的模型标签中分别点选对话模型和嵌入模型。

#### 「未在 OpenAI 兼容服务中找到…」

- LM Studio 需要先在界面中加载模型（仅下载不够），模型列表才会出现。
- 模型名区分大小写，按列表原样填写。
- 兼容服务若没有实现 `/models`，状态检查会失败，但实际对话 / 嵌入可能仍可用。

#### 「OpenAI 兼容服务 API Key 无效」

本地 LM Studio 通常不需要 Key，留空即可；只有调用云端兼容 API 时才按服务商要求填写。Key 会以 `Authorization: Bearer` 发送，留空时不会带该请求头。

#### 嵌入维度异常

兼容嵌入请求不发送 `dimensions`，维度由服务返回结果自动推断。同一模型前后返回不同维度时会报错，检查是否在服务端切换了模型，或网关改写了响应。

## 3. 导入与索引

### 文档一直显示「解析索引中…」

- 大文件或首次拉取模型会较慢，先等一会儿。
- 嵌入侧不可用时会卡在嵌入阶段；查看状态按钮和「测试连接」。
- 如果应用在索引中崩溃或被关闭，重启后会变成「上次索引未完成」。

### 「上次索引未完成（应用可能被关闭），请重试」

这是正常的崩溃恢复。点击文档右侧的重试图标，或打开文档后点「重建索引」。

### 「索引文件缺失或损坏，请重建索引」

`doc.json` 或 `vectors.bin` 丢失、截断或维度异常。重建该文档即可；如果反复出现，检查磁盘空间与是否被其他程序修改。

### 「源文件缺失，无法重建索引」

库内副本被删除或移动。删除该条目后重新导入原文件。

### 索引失败的文档还能预览吗

可以。失败的文档也能点开：弹窗会显示失败原因，并尽量展示上次解析出的片段；纯文本和 Markdown 在索引完成前会直接回退到库内保存的原文。其他格式在重试成功前只能用「打开原文件」查看。确认模型连接恢复后点「重试索引」，弹窗会在重建完成后自动刷新。

### 导入后没有出现文档

- 检查扩展名是否受支持。
- 文件夹导入会跳过隐藏文件和隐藏目录，并限制 8 层、5000 个文件。
- 选择代码仓库时，`node_modules` 等普通目录也会被扫描；如果文件过多，分批选择更稳妥。
- 看右下角提示是否显示「成功 N 个，失败 M 个」。

### 拖拽没有反应

某些程序拖出的不是真实文件路径。改用「导入文件」或「导入文件夹」。

### PDF 导入失败

错误「这个 PDF 没有可提取的文字，可能是扫描件」表示 PDF 只有图片。处理方式：

1. 把页面截图作为图片导入，并配置视觉模型或 OCR 语言数据。
2. 先用外部 OCR 工具生成可搜索 PDF，再导入。

### 图片导入失败

按顺序检查：

1. 设置里是否填写了可用的视觉模型；填写后需要本机 Ollama 正在运行。
2. 没有视觉模型时，`resources/tessdata` 是否有对应语言数据，开发环境可运行 `npm run fetch-ocr`。
3. 「OCR 语言」是否与语言数据一致，默认 `chi_sim+eng`。
4. 图片是否确实包含文字；纯图片会提示没有识别到文字。

视觉模型失败会自动回退到 OCR；如果两者都失败，错误信息会同时给出视觉模型失败原因。

### 同一个文件出现多次

当前不做内容去重，重复导入会生成多个条目。删除多余条目即可。

## 4. 检索与回答

### 「知识库还是空的」或「请先导入笔记」

没有就绪文档。等待索引完成，或先处理失败文档。

### 问题向量化失败

嵌入侧不可用。检查 Key、余额、地址和维度，再试。

### 回答总是「笔记中没有找到相关内容」

- 文档是否「就绪」。
- 问题是否包含笔记中的关键词或专有名词。
- 文档是否只是图片且 OCR 质量很差。
- 是否刚切换过嵌入模型或维度但没有重建索引。
- 尝试换一种更具体的问法；BM25 与向量是互补的。

### 切换模型后旧文档检索不到

不同提供方、模型或维度的向量不能混用。左侧会出现「嵌入模型已变更」提示：

1. 点击「重建」。
2. 等待所有文档重新索引完成。
3. 再提问。

重建期间，旧文档仍能通过 BM25 关键词命中，但向量召回会跳过不匹配的文档。

### 回答引用不相关或漏掉关键内容

- 打开引用文档，检查片段是否完整、表头是否保留。
- 提高「引用片段数」和「上下文字符上限」。
- 长表格 / 长文可以适当增大分块大小后重建。
- 降低温度，减少模型自由发挥。
- 确认问题中没有歧义词。

### 回答提到资料之外的内容

系统提示词要求只依据资料作答，但模型仍可能不遵守。可以降低温度、减少片段数量、让问题更明确；必要时换用更强的对话模型。引用卡片用于人工核对。

## 5. 本地 Ollama

### 无法连接 Ollama

确认服务在运行：

```bash
ollama --version
curl http://127.0.0.1:11434/api/tags
```

如果桌面端已启动但仍失败，检查设置里的地址和端口，以及代理设置中的 `NO_PROXY`。

### 缺少模型

错误会写明模型名，执行：

```bash
ollama pull qwen3:4b
ollama pull bge-m3
```

设置里的模型标签可以直接点选已安装模型。

### 显存不足或速度很慢

- 换更小的对话模型或嵌入模型。
- 降低「引用片段数」和「上下文字符上限」。
- 关闭其他占用显存的程序。
- Ollama 会把放不下的层放到 CPU，速度下降但通常不会崩溃。

### 图片视觉模型不可用

视觉模型始终走 `ollamaUrl`，即使对话和嵌入都使用云端。未启动 Ollama 时，视觉模型调用会失败并回退到本地 OCR。

## 6. 开发与构建

### 启动时报找不到 Electron

npm 11 可能拦截 postinstall，手动补装：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js
```

PowerShell：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"; node node_modules/electron/install.js
```

### OCR 报缺少语言数据

```bash
npm run fetch-ocr
npm run check-ocr
```

也可以手动下载 `chi_sim.traineddata.gz`、`eng.traineddata.gz` 放到 `resources/tessdata`。

### 打包后 OCR / tesseract 报错

确认 `package.json` 中：

- `resources/tessdata` 在 `extraResources` 中。
- `tesseract.js` 与 `tesseract.js-core` 在 `asarUnpack` 中。

重新执行 `npm run package`，不要只复制旧的 `release` 目录。

### 冒烟测试失败

`npm run smoke` 不需要真实模型，失败通常说明核心逻辑或依赖被改动。先看失败项：

- 解析 / 切块相关：检查对应 parser 或 chunker。
- mock 客户端相关：检查 SSE 读取、分批或响应解析。
- 文件权限相关：确认临时目录可写。

不要把真实 API Key 写进 `scripts/smoke.ts`。

## 7. 数据恢复与重置

### 只重置设置

退出应用，重命名或删除：

```text
%APPDATA%\JydNote\settings.json
```

再次启动会生成默认设置。API Key 需要重新填写或通过环境变量提供。

### 只重建索引

优先在界面中操作：

- 单篇：文档弹窗 →「重建索引」。
- 全部：左侧「嵌入模型已变更」提示中的「重建」；或对每个失败文档点重试。

### 清空知识库

退出应用后删除：

```text
%APPDATA%\JydNote\library
```

这会删除库内保存的原文件副本。确认原文件仍在别处后再操作。

### 迁移到另一台电脑

退出应用后复制整个 `%APPDATA%\JydNote`。目标机器的模型配置、Key 和知识库会一起迁移。不同机器上如果模型或维度不同，需要重建索引。

## 8. 收集诊断信息

反馈问题时可提供：

- 状态按钮的悬停内容（对话 / 嵌入两行）。
- 「测试连接」的完整结果（遮挡 Key）。
- 失败文档的错误文字。
- 问题发生在导入、问答还是启动阶段。
- `npm run typecheck`、`npm run smoke`、`npm run build` 的结果。
- 主进程终端的报错（不要包含 Authorization 头或 Key）。
