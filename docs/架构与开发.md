# 架构与开发

本文面向维护者，说明进程边界、数据流、存储格式、检索实现、测试与扩展方式。

## 1. 技术栈

| 层 | 选型 |
| --- | --- |
| 桌面容器 | Electron 45 |
| 构建 | electron-vite 6 + Vite 8 |
| 界面 | React 19 + TypeScript 7 |
| 主进程 | CommonJS，Node.js 20+ |
| 文档解析 | mammoth + turndown、SheetJS、unpdf、JSZip + @xmldom/xmldom、tesseract.js |
| 模型服务 | DeepSeek / 阿里云百炼 / LM Studio 等 OpenAI 兼容接口、Ollama |
| 存储 | 普通文件（JSON + 二进制向量），无数据库、无原生扩展 |

## 2. 进程与安全边界

```text
┌──────────────────────────┐
│ Renderer（React）        │  只负责界面与状态编排
│ contextIsolation: true   │  无 Node 权限
│ nodeIntegration: false   │
└────────────┬─────────────┘
             │ window.jyd（contextBridge）
┌────────────▼─────────────┐
│ Preload                  │  白名单 IPC 封装
└────────────┬─────────────┘
             │ ipcMain / ipcRenderer
┌────────────▼─────────────┐
│ Main                     │  文件、解析、向量、网络、密钥
└──────────────────────────┘
```

- 渲染进程不能直接读文件或发模型请求，所有能力都通过 preload 暴露的方法调用。
- API Key 由主进程持久化并用于发起请求；设置界面会通过 IPC 读取 Key 到渲染进程内存中用于编辑和「测试连接」，但不会写入日志或上传到其他位置。
- 云端请求由主进程发出；问答流式文本和引用元数据再通过 IPC 推给渲染进程。
- 设置文件是明文 JSON，安全边界依赖操作系统账户与磁盘权限。

## 4. 导入流水线

```text
选择文件 / 文件夹
  → 递归收集路径与相对目录（跳过隐藏项，深度 ≤ 8，最多 5000）
  → 过滤支持的扩展名、去重路径
  → 登记导入目录到 folders.json
  → 串行队列逐个处理
      → 复制原文件到 library/docs/<id>/source.*
      → 按格式解析为 TextBlock[]
      → 切块为 ChunkMeta[]
      → 生成向量（按提供方分批）
      → 写 doc.json + vectors.bin + index.json
  → 广播 library:changed
```

关键实现：

- `LibraryService` 用 `queue: Promise`（`enqueue()` 封装）串行化导入、重建、删除与笔记写入，避免并发写索引或写回已删除的文档。
- 每次导入使用随机 UUID 作为文档 ID；同一文件重复导入不会自动去重。
- 应用内新建 / 编辑笔记复用同一套「解析 → 切块 → 嵌入 → saveDoc」流程：`createNote` / `updateNote` 先在队列内以 UTF-8 原子写入 `docs/<id>/source.md|txt` 并 `upsertMeta`（状态 `indexing`），返回后把 `indexStoredSource()` 排进队列后台索引；IPC 不等嵌入完成。`importOne` 发现源路径已在库内时不再复制，因此不会碰到外部原文件。
- `importOne` 在 `saveDoc` 前和错误写回前会重新读取最新 `DocMeta`：文档已被删除则放弃提交，已被移动则沿用最新 `folder`，避免索引期间的操作被旧快照覆盖。
- 进度通过 `import:progress` 事件广播，阶段为 `copy` / `parse` / `chunk` / `embed` / `save` / `done` / `error`。
- 文件夹导入会写入 `DocMeta.folder`（相对所选文件夹的路径，`/` 分隔，含所选文件夹名），并把目录路径登记到 `folders.json`；单文件导入不带该字段。左侧 `DocList` 结合两者构建可折叠目录树，手动创建的空目录也能保留。
- 手动目录操作都在 `KnowledgeBase` 内完成：新建 / 重命名 / 删除目录、批量移动文档。移动会先校验全部文档和目标目录，再统一写一次 `index.json`；重命名会同步改掉所有子目录和文档的 `folder` 前缀；删除目录时文档与子目录上移到父目录。
- 启动时 `KnowledgeBase.load()` 会把残留的 `indexing` / `pending` 状态改成 `error`，提示上次索引未完成。
- 就绪文档在加载时会校验 `doc.json`、`vectors.bin` 和维度，损坏则标记为失败，可重建。

预览链路：

```text
DocList 点击 → DocViewer → library:content
  → TXT / Markdown：读库内 source.* 原文（解码并统一换行）
  → Word：mammoth → Markdown，渲染排版与表格
  → Excel / CSV：SheetJS 生成工作表预览（最多 400 行 × 40 列）
  → PDF / 图片：返回 jyd-file:// 地址，PDF 用 Chromium 内建阅读器
  → PPT：解析 OOXML 版式、文字、图片与表格，按比例重绘幻灯片
  → 预览失败 / 不可用：回退到 chunk 文本或 doc.json
```

TXT / Markdown 不展示切块拼接结果，因为片段重叠和〔标题〕标记适合检索、不适合阅读。渲染进程用 `Markdown` 组件渲染 Markdown，并提供「预览 / 原文」切换；其他格式由 `DocPreview` 组件族渲染。`jyd-file://` 是在主进程注册的特权协议，只允许读取知识库根目录内的文件，供 PDF 阅读器与图片使用。

主题链路：

```text
settings.json(theme) → AppSettings.theme（唯一持久化来源）
  → applyTheme() 写 html[data-theme]
  → styles.css 的 :root / :root[data-theme='dark'] 语义变量
  → main.tsx 用 localStorage 缓存提前着色，避免首屏闪白
```

主进程启动和保存设置时同步 `nativeTheme.themeSource`，让原生标题栏与下拉框跟随；窗口 `backgroundColor` 也按已保存主题选择。设置弹窗里的切换通过 `onThemePreview` 只做临时预览，取消时回落到已保存主题。新增颜色一律加到 `:root` 与深色覆盖块中，组件里不要写死浅色。

## 5. 存储格式

```text
%APPDATA%\JydNote\library\
├─ index.json                  DocMeta[]
├─ folders.json                目录路径 string[]（含手动创建的空目录）
└─ docs\<id>\
   ├─ source.<ext>             原始文件副本，或应用内写入 / 编辑的笔记
   ├─ doc.json                 { "chunks": ChunkMeta[] }
   └─ vectors.bin              Float32，行优先，chunkCount × dim
```

`DocMeta` 主要字段：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID |
| `name` / `ext` / `kind` / `size` | 文件信息 |
| `status` | `pending` / `indexing` / `ready` / `error` |
| `chunkCount` | 片段数 |
| `embedProvider` / `embedModel` / `dim` | 向量空间标识 |
| `sourceRel` | 相对 library 根目录的源文件路径 |
| `folder` | 文档所在的知识库目录（`/` 分隔）；导入时来自原文件夹，之后可通过移动操作调整；旧索引没有该字段时显示在根级 |
| `error` | 失败原因 |

`ChunkMeta` 主要字段：

| 字段 | 说明 |
| --- | --- |
| `id` | `<docId>:<index>` |
| `text` | 片段正文 |
| `headingPath` | 标题层级，Markdown / Word 常用 |
| `page` / `sheet` | PDF 页码 / 工作表名 |
| `charStart` / `charEnd` | 在解析文本中的大致字符位置 |

## 6. 解析与切块

| 格式 | 实现 | 特性 |
| --- | --- | --- |
| TXT | 自定义解码 | 自动识别 UTF-8 / UTF-16 / GBK / GB18030；按段落聚合 |
| Markdown | 自定义解析 | 标题树、代码围栏；`#` 在代码中不误判 |
| Word | mammoth → HTML → turndown | 复用 Markdown 标题结构；单元格段落压平后转为 Markdown 表格 |
| Excel / CSV | SheetJS | 每个工作表转 Markdown，每 12 行重复表头，单单元格截断 200 字符 |
| PDF | unpdf | 按页提取，保留页码；清理软换行 |
| PPT | JSZip + @xmldom/xmldom | 按 `presentation.xml` 顺序读取幻灯片；文本框、表格、备注进入索引，同时保留 EMU 坐标与字号用于预览；图片以 data URL 内联 |
| 图片 | Ollama 视觉模型 / tesseract.js | 先尝试视觉模型，失败回退 OCR |

切块要点：

- 按句末标点、换行切分单元，超过 `chunkSize` 才开新块。
- 超长无标点文本会硬切。
- 重叠优先从句子边界开始，最多为分块上限的一半。
- 少于 40 字符的尾块，在同一标题 / 页码下合并到前一块。
- 合并后允许达到 `chunkSize × 1.3`。
- 所有 chunk 重新编号，保证 `id` 连续。

## 7. 检索与回答

```text
question
  → embedTexts(settings, [question])
  → hybridSearch(vector, text, embedModel, embedProvider, topK, docIds?, candidateLimit)
      ├─ 向量召回：宽召回 max(20, topK × 3)
      │   只比较 ready 且 provider/model/dim 全部匹配的文档
      └─ BM25 召回：宽召回同上
          文档名 + 标题路径 + 正文一起建倒排
  → RRF：score += 1 / (60 + rank + 1)
  → 单文档最多 4 条
  → 开启重排序时保留 max(16, topK × 2) 条候选（最多 50）
  → qwen3-rerank 重新打分；失败时退回 RRF 顺序
  → 取前 topK
  → 上下文预算：前 3 条无条件保留，之后受 maxContextChars 限制
  → 系统提示词要求只依据资料作答、标注 [n]
  → chatStream 流式返回
```

空结果时不会调用对话模型，而是直接返回「没有检索到相关内容」的提示。

引用数据 `SourceItem` 与上下文分开传递：界面先收到来源卡片，再逐步接收回答文本。`SourceItem` 只带文档名、标题路径和页码等定位信息，不携带片段正文，避免把检索内容重复推给渲染进程；正文只进入提示词上下文。

## 8. 模型提供方

`core/models.ts` 是唯一分发点：

| 能力 | DeepSeek / 百炼 | LM Studio / OpenAI 兼容 | Ollama |
| --- | --- | --- | --- |
| 对话 | `POST /chat/completions`，SSE，带 `thinking: disabled` | `POST /chat/completions`，SSE，不带 `thinking` | `POST /api/chat`，NDJSON |
| 嵌入 | `POST /embeddings`，每批 10 条，带 `dimensions` | `POST /embeddings`，每批 10 条，无 `dimensions` | `/api/embed`，回退 `/api/embeddings` |
| 状态 | `GET /models`（必填 Key） | `GET /models`（Key 可选） | `GET /api/tags` + `/api/version` |
| 重排序 | `POST /compatible-api/v1/reranks`（404 时回退原生 `/api/v1/services/rerank/...`） | 不支持 | 不支持 |
| 视觉 | 不支持 | 不支持 | `/api/generate` |

云端与兼容服务实现要点：

- SSE 读取器处理跨分片行缓冲、`data:` 前缀、注释行和多行 data。
- 忽略 `reasoning_content`，只拼接 `delta.content`。
- 百炼响应按 `index` 排序，再校验数量与维度，最后 L2 归一化。
- OpenAI 兼容嵌入不传 `dimensions`，维度取第一批返回值；后续批次维度不一致直接报错。
- 兼容服务 Key 为空时不发送 `Authorization`，适配 LM Studio 默认不鉴权。
- 错误统一翻译为中文：401 Key 无效、402 余额不足、429 限流、400 超长、404 模型不存在。

## 9. IPC 契约

| 通道 | 方向 | 说明 |
| --- | --- | --- |
| `library:list` | invoke | 列出文档 |
| `library:list-folders` | invoke | 列出目录路径 |
| `library:create-folder` | invoke | 在指定父目录下新建目录 |
| `library:rename-folder` | invoke | 重命名目录（含子目录与文档） |
| `library:delete-folder` | invoke | 删除目录，内容上移到父目录 |
| `library:move-docs` | invoke | 批量把文档移动到指定目录或根级 |
| `library:import` | invoke | 导入路径（文件或目录） |
| `library:pick` | invoke | 系统文件选择器 |
| `library:pick-folder` | invoke | 系统目录选择器 |
| `library:remove` | invoke | 删除文档与库内副本 |
| `library:create-note` | invoke | 新建 Markdown / TXT 笔记并后台索引 |
| `library:update-note` | invoke | 改写库内笔记副本并重建索引 |
| `library:content` | invoke | 读取预览内容（TXT / Markdown 优先库内原文） |
| `library:reindex` | invoke | 重建全部 |
| `library:reindex-doc` | invoke | 重建单篇 |
| `library:open-source` | invoke | 系统程序打开副本 |
| `settings:get` / `settings:save` | invoke | 设置读写 |
| `models:status` | invoke | 当前配置的模型状态 |
| `models:test` | invoke | 用未保存配置测试连接 |
| `rag:ask` | invoke | 开始问答（立即返回，后续走事件） |
| `rag:abort` | invoke | 取消某个请求 |
| `rag:stream` | send | `sources` / `delta` / `done` / `error` |
| `import:progress` | send | 导入阶段进度 |
| `library:changed` | send | 文档列表需要刷新 |

每个问答请求都带 `requestId`，取消控制器按该 ID 存在内存 Map 中；取消后发送 `done`，不会留下悬挂引用。

## 10. 开发与验证

### 环境

需要 Node.js 20+（开发使用 Node 24）。首次安装：

```bash
npm install
```

npm 11 可能拦截 Electron 的 postinstall。若 `node_modules/electron/dist/electron.exe` 不存在：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js
```

### 常用命令

```bash
npm run dev         # 开发模式
npm run typecheck   # 主进程 + 渲染进程类型检查
npm run smoke       # 冒烟测试，不依赖真实模型

npm start           # 预览构建产物
```

- 输出目录 `release/`。

## 11. 扩展指南

### 新增文件格式

1. 在 `src/main/core/parsers/` 新建解析器，返回 `ParsedDoc`。
2. 在 `parsers/index.ts` 注册扩展名与 `DocKind`。
3. 在 `parseDocument` 中分支调用。
4. 在 `SUPPORTED_EXTENSIONS` 中加入扩展名。
5. 在 `shared/types.ts` 的 `DocKind` 中增加类型，并更新界面图标 / 标签。
6. 在 `smoke.ts` 增加一个最小样例。

解析器只需产出 `TextBlock[]`，切块、向量化、检索会自动复用。

### 新增模型提供方

1. 实现 `embedTexts` 与 `chatStream` 所需的客户端函数，保持返回格式为 `Float32Array[]` 和流式回调。
2. 在 `core/models.ts` 中按 provider 分发。
3. 扩展 `AppSettings` 与 `normalizeSettings`，补齐默认值、枚举与范围校验。
4. 在设置界面增加提供方选项和对应字段，复用 `SegmentedControl`、`SecretField`；模型列表用 `ModelTags`，连接配置用 `OpenAiCompatibleFields` 这类可复用组件。
5. 状态检查要分别返回对话、嵌入两侧的结果。
6. 注意向量空间标识：新 provider 必须写入 `embedProvider`，否则会与旧向量混用。

### 替换向量存储

对外只需要保留 `KnowledgeBase.hybridSearch(queryVector, queryText, embedModel, embedProvider, topK, docIds?)` 的语义。可以替换内部实现为 HNSW、`sqlite-vec` 或 LanceDB，但需要同时处理：

- 向量维度与 provider 一致性。
- 删除文档后的索引清理。
- 重建索引。
- 关键词召回与 RRF 融合。

### 增加「只查部分文档」

数据层已经支持：`hybridSearch(..., docIds)`，`ChatRequest` 也带可选 `docIds`。当前没有界面入口。实现时建议：

- 在 Sidebar 或 ChatPanel 增加文档多选组件。
- 把选中的 ID 传入 `window.jyd.ask`。
- 未选择时传 `undefined`，保持全库检索。
- 在消息上展示本次检索范围，避免用户误以为查了全库。

## 12. 代码约定

- 前端能力优先写成组件，选择器、弹窗、密钥输入等复用现有组件，不把复杂交互散落在页面里；提供方模型列表用 `ModelTags`，LM Studio / 兼容服务配置用 `OpenAiCompatibleFields`，目录命名与移动文档分别用 `FolderNameDialog` / `MoveDocDialog`，主题切换用 `ThemePicker`。
- `App.tsx` 只做状态与事件编排；样式集中在 `styles.css`，交互封装在组件内。
- 主进程按「解析 / 切块 / 模型 / 存储 / 检索」分层，新增逻辑优先放进 `core/`，不要塞进 IPC 层。
- 面向用户的错误信息使用中文，并给出可执行的下一步。
- 提交信息使用中文，沿用 `type(scope): 摘要`，正文解释「为什么改」。
