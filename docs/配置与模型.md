# 配置与模型

应用把「对话」和「嵌入」拆成两个独立的提供方，可以任意组合：

- 云端：DeepSeek 负责回答，阿里云百炼负责向量化（默认）。
- 完全本地：两者都用 Ollama。
- LM Studio / OpenAI 兼容：指向 LM Studio 本地服务，或任意 OpenAI 兼容 API；对话与嵌入可分别选择。
- 混合：例如本地 Ollama 回答 + 百炼向量化，或云端回答 + 本地向量化。

设置只保存在本机 `%APPDATA%\JydNote\settings.json`，保存时会做类型、枚举和数值范围校验。

## 1. 默认配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `theme` | `light` | 界面主题：`light` / `dark`，只影响显示，与索引和模型无关 |
| `chatProvider` | `deepseek` | 对话提供方：`deepseek` / `openai` / `ollama` |
| `chatModel` | `deepseek-flash` | 对话模型名；切到 `openai` 时默认为空，需从服务列表选择 |
| `deepseekApiKey` | 空 | 留空时读取环境变量 `DEEPSEEK_API_KEY` |
| `deepseekBaseUrl` | `https://api.deepseek.com` | OpenAI 兼容根地址，也兼容自建网关 |
| `embedProvider` | `dashscope` | 嵌入提供方：`dashscope` / `openai` / `ollama` |
| `embedModel` | `text-embedding-v4` | 百炼嵌入模型名；切到 `openai` 时默认为空 |
| `dashscopeApiKey` | 空 | 留空时读取环境变量 `DASHSCOPE_API_KEY` |
| `dashscopeBaseUrl` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 百炼 OpenAI 兼容地址 |
| `embedDimensions` | `1024` | 百炼向量维度；`openai` / `ollama` 由返回值推断，不受此项影响 |
| `rerankEnabled` | `false` | 是否在混合检索后调用 `qwen3-rerank` 重排序；开启后会额外请求百炼 |
| `rerankModel` | `qwen3-rerank` | 重排序模型名；使用百炼 Key 与 Base URL 所在地域 |
| `openaiBaseUrl` | `http://127.0.0.1:1234/v1` | LM Studio 或任意 OpenAI 兼容服务的根地址 |
| `openaiApiKey` | 空 | 兼容服务 Key，可选；LM Studio 本地服务通常留空 |
| `ollamaUrl` | `http://127.0.0.1:11434` | 本地模式与图片视觉识别使用 |
| `visionModel` | 空 | 留空走本地 OCR；填写则优先用视觉模型 |
| `topK` | `8` | 交给模型的引用片段数 |
| `chunkSize` | `900` | 分块字符上限 |
| `chunkOverlap` | `120` | 分块重叠字符数 |
| `temperature` | `0.2` | 生成温度 |
| `maxContextChars` | `12000` | 资料片段总字符预算 |
| `ocrLangs` | `chi_sim+eng` | tesseract 语言组合 |

## 2. 对话模型

### DeepSeek 云端

- 请求地址：`{deepseekBaseUrl}/chat/completions`。
- 协议：OpenAI 兼容 SSE，逐行读取 `data:`，以 `data: [DONE]` 结束。
- 请求中会带上 `thinking: { type: "disabled" }`，避免笔记问答前出现长时间思考。
- 只拼接 `choices[0].delta.content`；如果服务返回 `reasoning_content`，不会显示给用户。
- 状态检查与「测试连接」会调用 `GET {base}/models`，并用它列出可选模型。

因此，使用第三方兼容网关时，网关需要同时支持 `/chat/completions` 和 `/models`；只支持对话、不支持模型列表的网关会显示「测试连接」失败，但仍可能可以正常问答。

### LM Studio / OpenAI 兼容服务

- 请求地址：`{openaiBaseUrl}/chat/completions`，OpenAI 兼容 SSE。
- 请求字段只有 `model`、`messages`、`stream`、`temperature`；不会发送 DeepSeek 专用的 `thinking` 参数。
- 同样只拼接 `delta.content`，忽略 `reasoning_content`。
- 状态检查与「测试连接」会调用 `GET {base}/models`，返回的模型列表可在设置里直接点击填入。
- API Key 可选：填写后发送 `Authorization: Bearer`；LM Studio 本地服务留空即可。
- 对话与嵌入共用同一个 `openaiBaseUrl` 和 `openaiApiKey`，LM Studio 可在同一服务中加载两类模型。
- 如果兼容服务没有实现 `/models`，状态检查会失败，但对话和嵌入请求本身可能仍然可用；此时可先忽略状态提示，直接测试导入与问答。

### 本地 Ollama

- 请求地址：`{ollamaUrl}/api/chat`，NDJSON 流式返回。
- 状态检查会读取 `/api/tags` 和 `/api/version`，并确认所填模型已经安装。
- 未安装时错误信息会提示执行 `ollama pull <模型名>`。

常用模型：

```bash
ollama pull qwen3:4b     # 4GB 显存左右的默认选择
ollama pull qwen2.5:7b   # 显存更充裕
ollama pull qwen2.5:3b   # 显存紧张
```

### 生成参数

| 参数 | 范围 | 影响 |
| --- | --- | --- |
| 温度 | 0–1.5 | 越低越稳定，笔记问答建议 0–0.3 |
| 引用片段数 | 1–30 | 越多资料越全，但更慢、更耗 token |
| 上下文字符上限 | 2000–64000 | 总资料预算；前 3 条片段即使超出预算也会保留 |

## 3. 嵌入模型

### 阿里云百炼

- 请求地址：`{dashscopeBaseUrl}/embeddings`。
- 请求字段：`model`、`input`、`dimensions`、`encoding_format: "float"`。
- 单次最多 10 条文本，客户端会自动按 10 条一批发送。
- 单条输入上限约 8192 tokens；超长会返回明确错误，处理方式是减小分块大小。
- 支持维度：`2048`、`1536`、`1024`、`768`、`512`、`256`、`128`、`64`。
- 返回值按 `index` 还原顺序，再做 L2 归一化后写入本地。
- 状态检查会发送一条 `连接测试` 文本，消耗极少额度。

更换模型或维度后，旧向量不能继续做向量检索，界面会提示重建索引。旧文档只会在 BM25 关键词检索中继续命中，因此不要忽略「重建」提示。

### LM Studio / OpenAI 兼容服务

- 请求地址：`{openaiBaseUrl}/embeddings`。
- 请求字段：`model`、`input`、`encoding_format: "float"`；不发送 `dimensions`，因为 LM Studio 等兼容服务不一定支持该参数。
- 单批最多 10 条，自动分批；响应按 `index` 还原顺序，再做 L2 归一化。
- 向量维度由第一批返回结果推断，同一模型前后维度不一致会直接报错。
- 状态检查通过 `GET /models` 确认模型存在，并列出可选嵌入模型。

切换兼容服务地址或嵌入模型后，旧向量不能继续做向量检索，需要重建索引。

### 本地 Ollama

- 优先调用 `/api/embed`，失败时回退到旧版 `/api/embeddings`。
- 中文推荐 `bge-m3`；显存紧张可用 `nomic-embed-text`。
- 向量维度由模型决定，设置里的「向量维度」只对百炼生效。

```bash
ollama pull bge-m3
```

### 向量空间一致性

每条文档在索引里记录：

- `embedProvider`：`dashscope`、`openai` 或 `ollama`
- `embedModel`：具体模型名
- `dim`：向量维度；百炼取设置值，`openai` / `ollama` 取服务返回的维度

检索时只有提供方、模型和维度都匹配的向量才参与向量召回。旧版本索引没有 `embedProvider` 字段，按本地 Ollama 处理。

## 4. API Key 与环境变量

界面里填写 Key 会把值写入本机设置文件。若输入框留空，则读取环境变量：

| 提供方 | 环境变量 |
| --- | --- |
| DeepSeek | `DEEPSEEK_API_KEY` |
| 阿里云百炼 | `DASHSCOPE_API_KEY` |

启动前设置：

```bash
# Git Bash / macOS / Linux
export DEEPSEEK_API_KEY="sk-..."
export DASHSCOPE_API_KEY="sk-..."

# Windows PowerShell
$env:DEEPSEEK_API_KEY="sk-..."
$env:DASHSCOPE_API_KEY="sk-..."
```

环境变量适合不想把 Key 写进设置文件的场景；界面填写优先于环境变量。

`openaiApiKey` 只在界面中配置，不读取环境变量；LM Studio 本地服务通常不需要填写，调用云端 OpenAI 兼容 API 时才需要。

### 安全说明

- 应用不会把 Key 写进日志、源码或测试文件。
- Key 在 `settings.json` 中是明文，不加密。
- 云端模式下，问答会把问题和命中的片段发送给对应服务商；导入文档时，文本分块会发送给嵌入服务商。
- `openaiBaseUrl` 指向本机 LM Studio 时数据不出本机；指向远程兼容服务时，请求内容同样会发送到该地址。
- 建议为这个应用单独创建 Key、设置额度上限，并定期轮换。
- 不要把带有 Key 的 `settings.json` 提交到代码仓库或共享目录。

## 5. 本地 Ollama 与图片识别

### 视觉模型

设置里的「视觉模型」始终通过 `ollamaUrl` 调用，与对话提供方无关。配置后，导入图片会优先让视觉模型提取文字和描述：

```bash
ollama pull qwen2.5vl:3b
```

然后把「视觉模型」填成 `qwen2.5vl:3b`。如果视觉模型调用失败，会自动回退到本地 OCR。

### 本地 OCR

未配置视觉模型时，图片使用 tesseract.js：

1. 确认 `resources/tessdata` 内有对应语言数据。
2. 开发环境运行 `npm run fetch-ocr`。
3. 设置里的「OCR 语言」默认为 `chi_sim+eng`，可按需改成其他组合。

OCR 只提取文字；需要理解图表、截图布局时，使用视觉模型更合适。

## 6. 分块与检索参数

### 分块

- 默认 900 字符，120 字符重叠。
- Markdown 按标题层级切块，代码围栏里的 `#` 不会被当成标题。
- 纯文本按段落聚合，单块最多约 1200 字符后进入 chunk 切分。
- Excel / CSV 每个工作表转 Markdown 表格，每 12 行重复一次表头。
- PDF 按页提取并保留页码。
- 过短尾块会合并，实际重叠会被限制在分块上限的一半以内。

修改分块参数不会自动重建旧索引；新参数只影响之后导入或手动重建的文档。

### 检索

```text
向量召回（宽召回 max(20, topK × 3)）
        + BM25 关键词召回（同样宽召回）
        → RRF 融合（k=60）
        → 单文档最多 4 条
        → 开启重排序时保留 max(16, topK × 2) 条候选
        → qwen3-rerank 重新打分（失败则退回 RRF 顺序）
        → 取前 topK 条
        → 按 maxContextChars 拼上下文
```

- 向量检索是暴力点积，个人笔记规模下足够快。
- BM25 使用中文单字 + 二元组 + 拉丁词，弥补向量模型对专有名词和短查询的不足。
- 单文档最多 4 条，避免一篇笔记占满上下文。
- 前 3 条片段即使超过字符预算也会保留，保证回答至少有可用资料。

### 重排序（qwen3-rerank）

- 默认关闭；在「设置 → 重排序」中开启后会多一次百炼请求。
- 使用「阿里云百炼 API Key」与 `dashscopeBaseUrl` 所在域名/地域；开启重排序时，「测试连接」会同时检查这一项。
- 请求优先走 `{根地址}/compatible-api/v1/reranks`（扁平请求体，读取 `results`），遇到 404/405 自动回退原生 `{根地址}/api/v1/services/rerank/text-rerank/text-rerank`（读取 `output.results`）。
- 返回的 `index` 是候选列表的 0 基下标，`relevance_score` 只在本次请求内可比；客户端按分数从高到低重排，并继续执行单文档最多 4 条的限制。
- 每次最多 500 条候选，单条 query / 文档上限 4000 tokens；为稳妥起见，客户端把 query 截到 2000 字符、每条片段截到 3000 字符再发送。
- 重排序失败（Key 无效、网络或额度问题）不会阻断回答：自动退回 RRF 顺序，只在主进程控制台记录原因。

调参建议：

| 现象 | 调整 |
| --- | --- |
| 回答漏掉细节 | 提高「引用片段数」和「上下文字符上限」 |
| 回答太慢 / token 消耗高 | 降低片段数和上下文字符上限 |
| 长表格或长文被截断 | 适当增大分块大小，或减小分块重叠 |
| 召回不相关 | 检查文档片段质量；尝试更具体的提问 |

## 7. 设置文件示例

路径：`%APPDATA%\JydNote\settings.json`。以下示例省略了真实 Key：

```json
{
  "theme": "light",
  "chatProvider": "deepseek",
  "chatModel": "deepseek-flash",
  "deepseekApiKey": "",
  "deepseekBaseUrl": "https://api.deepseek.com",
  "embedProvider": "dashscope",
  "embedModel": "text-embedding-v4",
  "dashscopeApiKey": "",
  "dashscopeBaseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
  "embedDimensions": 1024,
  "rerankEnabled": false,
  "rerankModel": "qwen3-rerank",
  "openaiBaseUrl": "http://127.0.0.1:1234/v1",
  "openaiApiKey": "",
  "ollamaUrl": "http://127.0.0.1:11434",
  "visionModel": "",
  "topK": 8,
  "chunkSize": 900,
  "chunkOverlap": 120,
  "temperature": 0.2,
  "maxContextChars": 12000,
  "ocrLangs": "chi_sim+eng"
}
```

正常使用建议通过界面修改，不要手工编辑；保存时会自动补全缺失字段并纠正越界值。

### 旧版本迁移

旧版本只支持 Ollama，没有 `chatProvider` / `embedProvider` 字段。读取到这种设置文件时，应用会自动按「对话和嵌入都用本地 Ollama」处理，避免升级后误用云端默认模型。

## 8. 高级示例

### 完全离线

```text
对话模型：本地 Ollama · qwen3:4b
嵌入模型：本地 Ollama · bge-m3
视觉模型：留空（使用本地 OCR）或 qwen2.5vl:3b
```

需要预先安装 Ollama、模型和 OCR 语言数据；运行期间不访问外网。

### 完全离线（LM Studio）

```text
对话模型：LM Studio / API · 已加载的对话模型
嵌入模型：LM Studio / API · 已加载的嵌入模型
服务地址：http://127.0.0.1:1234/v1
API Key：留空
视觉模型：留空（使用本地 OCR）
```

需要在 LM Studio 中提前下载并加载两类模型，并启动 Local Server；运行期间不访问外网。把服务地址换成内网自建的 OpenAI 兼容网关，也可以得到同样的离线效果。

### 云端回答 + 本地向量化

```text
对话模型：DeepSeek 云端 · deepseek-flash
嵌入模型：本地 Ollama · bge-m3
```

这样导入文档时不需要把文本发送给嵌入服务商，但提问仍会把命中的片段发送给 DeepSeek。注意：首次导入需要本地 Ollama 已安装 `bge-m3`。

### 本地回答 + 云端向量化

```text
对话模型：本地 Ollama · qwen3:4b
嵌入模型：阿里云百炼 · text-embedding-v4
```

导入时文本分块会发送给百炼生成向量，但问答内容留在本机模型处理。
